title: "Generate Stripe OAuth URL"
openapi: "platform POST /platform/oauth_url"
---

<Info>
  Generates a Stripe Connect OAuth URL for a platform organization. Use this to allow your tenants to connect their Stripe accounts through the OAuth flow.
</Info>

## OAuth Flow

After generating the OAuth URL:

1. Redirect your tenant to the `oauth_url`
2. User authorizes their Stripe account
3. Stripe redirects to Autumn's callback URL
4. Autumn processes the authorization and redirects to your `redirect_url`
5. Your `redirect_url` receives `success=true` on success, or `success=false`, a stable `error` code, and a human-readable `message` on failure.

After the redirect, call [Get Stripe Connection](/api-reference/platform/getStripeConnection) to refresh the connection shown in your application. Do not treat a missing `connected_at` on a historical connection as a failure.

## Reconnect and account ownership

A Stripe OAuth account can belong to one Autumn organization per environment. Authorizing the same account again for the same organization refreshes the connection. Trying to connect an account already linked to a different organization returns `account_already_connected`.

Conflict details are limited to organizations owned by your own master organization. A conflict with another platform does not disclose that platform's organization identity.

For a same-platform conflict, `connected_org_slug` and `connected_org_name` identify the existing organization. The slug is the public tenant slug, without the master-organization suffix.

To switch accounts, first [disconnect the existing OAuth connection](/api-reference/platform/disconnectStripe), then generate a new OAuth URL. Disconnecting does not delete the Stripe account or its subscriptions.

## Error handling

Use `error` for application logic and display `message` to the user. Start a fresh OAuth flow after a failed callback: each `oauth_url` is valid for **60 minutes** and can be used **once**.

| Error | Meaning |
| --- | --- |
| `access_denied` | The user cancelled Stripe authorization. |
| `oauth_authorization_failed` | Stripe returned another authorization error. |
| `missing_parameters` | The callback is missing its state or authorization code. |
| `state_expired` | The `oauth_url` was opened more than 60 minutes after it was generated. |
| `state_already_used` | The `oauth_url` was already used to complete or cancel a connection. |
| `invalid_state` | The state was not issued by Autumn or is not valid for Stripe. |
| `org_not_found` | The target organization could not be found or is no longer owned by this platform. |
| `account_id_not_found` | Stripe's token response did not identify an account. |
| `account_already_connected` | Another organization already uses the account in this environment. |
| `account_mismatch` | The account differs from the tenant's separate secret-key connection. |
| `account_mismatch_check_failed` | Autumn could not verify the separate secret-key connection. |
| `oauth_callback_failed` | The token exchange, authorization check, or connection update failed. |

<Note>
  The organization must have been created via the platform API before generating an OAuth URL.
</Note>

<Note>
  Expired and already-used links still return to your `redirect_url`. Only a state Autumn cannot verify (`invalid_state`) returns to Autumn's default callback destination, because Autumn cannot trust a return URL it did not sign.
</Note>
