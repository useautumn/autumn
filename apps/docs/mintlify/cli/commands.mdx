Run `atmn --help` or `atmn <command> --help` to see the latest options.

## Global flags

These work with every command.

| Flag | Description |
|------|-------------|
| `-p, --prod` | Target production instead of sandbox |
| `--sandbox <id>` | Target a specific sandbox |
| `-l, --local` | Use `localhost:8080` API server |
| `-c, --config <path>` | Path to config file (default: `autumn.config.ts`) |
| `--headless` | Force non-interactive mode (for CI/agents) |
| `-V, --version` | Show CLI version |

## Authentication

### `atmn login`

Authenticate with Autumn via OAuth. Opens your browser, lets you select an organization, and saves sandbox + production API keys to `.env`.

```bash
atmn login
```

In non-TTY environments (CI), it prints a URL you can open manually.

| Flag | Description |
|------|-------------|
| `--keyless` | Create a sandbox org without an account |
| `--claim <email>` | Link a keyless org to your account |

### `atmn env`

Show your current organization, environment and key:

```bash
atmn env
```

## Configuration

### `atmn init`

Create an `autumn.config.ts` in your project, pull your existing plans into it, and install the agent skills. Prompts for login if you haven't authenticated yet.

```bash
atmn init
```

| Flag | Description |
|------|-------------|
| `--login` | Sign in on the web |
| `--keyless` | Create a sandbox org without an account |
| `--path <dir>` | Folder for the config package (monorepos) |
| `--name <name>` | Name of the config package (monorepos) |

### `atmn push`

Push your local `autumn.config.ts` to Autumn.

```bash
atmn push [options]
```

| Flag | Description |
|------|-------------|
| `-y, --yes` | Apply the changes |
| `-d, --dry-run` | Preview only, even with `--yes` |

The CLI compares your local config with what's in Autumn and shows a summary of changes. Nothing is applied until you pass `--yes`.

### `atmn pull`

Pull plans and features from Autumn into your local `autumn.config.ts`.

```bash
atmn pull [options]
```

| Flag | Description |
|------|-------------|
| `--overwrite` | Rewrite the config from Autumn instead of updating it in place (needs `--yes`) |
| `--include-mappings` | Keep Stripe and RevenueCat mappings in the pulled config |

By default, `pull` does a smart in-place update: it adds new features and plans, updates existing ones, and removes deleted ones while preserving your formatting. Use `--overwrite --yes` to rewrite `autumn.config.ts`, `features.ts`, `plans.ts` and `rewards.ts` from Autumn. Nothing is deleted, and files that don't import `atmn` are left alone.

### `atmn reset`

Delete all plans, features and customers in your sandbox. Sandbox only.

```bash
atmn reset --yes
```

## Skills

### `atmn skills`

List the agent skills bundled with the CLI, or print one:

```bash
atmn skills
atmn skills autumn-catalog
```

### `atmn skills install`

Write the skills next to your config so your coding agent can use them. `atmn init` does this for you.

| Flag | Description |
|------|-------------|
| `--dir <dir>` | Install to a different folder |
| `--link` | Run `npx skills add` afterwards |

### `atmn skills update`

Update installed skills to the version bundled with this CLI.

## Sandboxes

Sandboxes are isolated copies of your organization, each with their own plans, customers and API key.

```bash
atmn sandbox list                  # Show your sandboxes
atmn sandbox create <name>         # Create one and save its key
atmn sandbox use <name>            # Target it in later commands
atmn sandbox use --clear           # Go back to your main sandbox
atmn sandbox delete <id> --yes     # Delete it
```

## Headless mode

The CLI automatically detects non-TTY environments and switches to headless mode with plain text output and no interactive prompts. You can also force it with `--headless`.

### Exit codes

| Code | Meaning |
|------|---------|
| `0` | Success |
| `1` | Error (network, auth, validation, or confirmation required) |
