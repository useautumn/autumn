For the latest help, run `atmn --help` or `atmn <command> --help`.

## Global flags

These work with every command.

| Flag | Description |
|------|-------------|
| `-p, --prod` | target production instead of sandbox |
| `--sandbox <sandboxId>` | target a specific sandbox |
| `-l, --local` | target a local server (default port 8080) |
| `--port <port>` | port of a local server (implies `--local`) |
| `-b, --base-url <url>` | send to this URL instead |
| `--client-id <id>` | OAuth client id the CLI identifies as |
| `-c, --config <path>` | `autumn.config.ts`, or the folder holding it |
| `--headless` | never prompt: print what a command needs and stop |
| `-V, --version` | print the version |

You cannot combine `-p` with `--sandbox`. If you pass `-p` while a sandbox is pinned, production wins.

## `atmn init`

Sets up the repo: connects to Autumn, creates the config, pulls your catalog and installs the skills.

```bash
atmn init [options]
```

| Flag | Description |
|------|-------------|
| `--path <dir>` | folder for the Autumn package (monorepos) |
| `--name <name>` | the package's name (monorepos) |
| `--login` | sign in on the web |
| `--keyless` | create a sandbox org now, no account needed |

If there is no `AUTUMN_SECRET_KEY` yet, `init` asks how you want to connect. Without a terminal it prints the two flags and stops. Pass one of them, not both.

## `atmn login`

Connects to Autumn and writes the org's keys to your `.env`.

```bash
atmn login [options]
```

| Flag | Description |
|------|-------------|
| `--keyless` | create a sandbox org now, no account needed |
| `--claim <email>` | link a keyless org to an account |

A plain `atmn login` opens a browser (or prints the URL if it can't) and writes `AUTUMN_SECRET_KEY` and `AUTUMN_PROD_SECRET_KEY`. `--keyless` creates a sandbox org with no account and writes `AUTUMN_SECRET_KEY` only. `--claim <email>` emails a link that attaches the keyless org to an account. Your key keeps working after that.

## `atmn env`

Shows the org, environment and key your commands will use.

```bash
atmn env [--json]
```

`--json` prints the raw response, including `notes` that say how to fix anything that looks wrong.

## `atmn push`

Previews `autumn.config.ts` against your catalog. `--yes` applies it.

```bash
atmn push [options]
```

| Flag | Description |
|------|-------------|
| `-y, --yes` | apply the changes the preview shows |
| `-d, --dry-run` | preview only, even with `--yes` |

`push` never asks questions. Without `--yes` it checks the config and prints the diff. With `--yes` it applies exactly that diff, deletions included.

After a successful `push --yes`, the CLI writes each row's `internalId` back into your config and lists any migration drafts it created.

## `atmn pull`

Writes your remote catalog back into `autumn.config.ts`.

```bash
atmn pull [options]
```

| Flag | Description |
|------|-------------|
| `--include-mappings` | keep processor mappings in pulled fixtures |
| `--overwrite` | discard the local config and pull the catalog fresh |
| `-y, --yes` | confirm `--overwrite` |

A plain `pull` edits the file in place: it adds rows the config did not have, updates changed ones, flips `active`, and fills in `internalId` and `versionSlug`. It can only edit rows written as plain objects. If a row is built with a spread, a helper or `.map()`, `pull` tells you which rows it cannot edit and writes nothing.

`--overwrite` deletes every TypeScript file in the config folder and rebuilds it from the server, so it needs `--yes`. Without `--yes` it tells you what would happen and stops.

## `atmn reset`

Wipes the sandbox's catalog and customers. `--yes` applies it.

```bash
atmn reset [-y]
```

Clears every customer, plan, feature and migration draft in the targeted sandbox. Keys and settings stay. Without `--yes` it names the sandbox and stops.

<Warning>
`reset` refuses to run with a live key.
</Warning>

## `atmn skills`

Lists, prints, installs and updates the agent skills bundled with the CLI.

```bash
atmn skills [name] [options]
```

| Argument / flag | Description |
|------|-------------|
| `[name]` | print this skill's `SKILL.md` |
| `--ref <path>` | print one of the skill's reference files instead |
| `--json` | print the skill as JSON |

The CLI carries `autumn-setup`, `autumn-catalog`, `autumn-integrate` and `autumn-concepts`. `push` and `pull` tell you when the copy next to your config is older than the CLI's.

### `atmn skills install`

Writes the skills next to your config.

| Flag | Description |
|------|-------------|
| `--dir <dir>` | write here instead of `<config folder>/skills` |
| `--link` | run `npx skills add <dir> --all` afterwards |

### `atmn skills update`

Rewrites installed skills that are older than the CLI's.

| Flag | Description |
|------|-------------|
| `--dir <dir>` | the install to update (default `<config folder>/skills`) |

## `atmn sandbox`

Manages isolated sandboxes. These subcommands always use your main `AUTUMN_SECRET_KEY`, even when a sandbox is pinned.

### `atmn sandbox list`

Shows your sandboxes, newest first. `--json` prints the raw response.

### `atmn sandbox use`

```bash
atmn sandbox use [query] [options]
```

| Argument / flag | Description |
|------|-------------|
| `[query]` | the sandbox's name or id |
| `--clear` | drop the pin so commands target the main sandbox |
| `--json` | print the result as JSON |

Pins `AUTUMN_SANDBOX_ID` in your `.env`. Every command targets that sandbox until you clear it. If you have no key for that sandbox yet, `use` creates one and saves it as `AUTUMN_SANDBOX_<ID>_SECRET_KEY`.

### `atmn sandbox create`

```bash
atmn sandbox create <name> [options]
```

| Argument / flag | Description |
|------|-------------|
| `<name>` | name for the sandbox |
| `--color <color>` | colour the dashboard labels it with |
| `--icon <icon>` | icon the dashboard labels it with |
| `--use` | pin it so later commands target it |
| `--json` | print the raw response |

The key is shown once, in the create response. If the CLI cannot write it to `.env`, it prints the key so you can save it yourself.

### `atmn sandbox delete`

```bash
atmn sandbox delete <id> [-y]
```

Deletes the sandbox, its catalog and its customers. Without `--yes` it names the sandbox and stops. It also removes that sandbox's key and pin from your `.env`.

## Environment variables

Read from `.env.local`, then `.env`, in the config folder, the repo root and the current directory. Anything already set in your shell wins.

| Variable | Used for |
|----------|----------|
| `AUTUMN_SECRET_KEY` | the sandbox key. The default for every command |
| `AUTUMN_PROD_SECRET_KEY` | the production key, used with `-p` |
| `AUTUMN_SANDBOX_<ID>_SECRET_KEY` | a named sandbox's key, used when that sandbox is pinned or passed to `--sandbox` |
| `AUTUMN_SANDBOX_ID` | the pinned sandbox, written by `atmn sandbox use` |
| `AUTUMN_BASE_URL` | send to this URL instead of Autumn's API |
| `AUTUMN_CLIENT_ID` | the OAuth client id the CLI identifies as |

If the key a command needs is missing, it stops before sending anything and tells you what to run:

```
AUTUMN_SECRET_KEY is not set. Run atmn login, or atmn login --keyless if you don't have an account.
AUTUMN_PROD_SECRET_KEY is not set. Run atmn login.
AUTUMN_SANDBOX_<ID>_SECRET_KEY is not set. Run atmn sandbox create, or add its key to your .env.
```

## Headless mode

With `--headless`, or whenever there is no terminal (CI, coding agents), commands never prompt. Instead they print the flag they need and stop. Run again with that flag to continue. `push` and `pull` never prompt anyway; `--yes` is their only gate.
