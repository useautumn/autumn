# Units of work: pooled balances through the worker

Design: `research.md` ("Pooled balances: decided"). Scope is customer-level pools only; license
pools and seat products are a later plan. Each unit is a thin slice through engine → worker →
postgres → server, ends with a passing test, and stops for review. One stacked branch per unit.

Order: the queue first (every later unit relies on it) → inserts (first end-to-end pooled attach
on the worker) → removals and expiry → resets → the last Postgres-only writers → the sweep.

## Decided

1. Contribution rows are never in worker memory; every op that touches one carries the row as the
   server read it, and the committer writes it. Hot paths never read them.
2. Every plan for a customer runs one at a time on the worker. Throughput evidence in `research.md`.
3. The synthetic pool entitlement stays a catalog row (Postgres, before the worker), like custom items.
4. No new `pooled_balances` columns; `pending_at_next_reset` is state only, rebuilt on load.

## Seat reads (added 2026-09-23, before prod)

The rollout switch is global, so every seat customer would read through the worker; hydration used
to cut seats and license pools, and the worker had no seat inheritance. Writes stay on Postgres +
evict (`writesNoLicenseSeats`, `writePostgresOnlyRows`). Done:

1. Hydration keeps a seat product, and a license pool, while the parent behind its license link is
   live (`licenseParentIsLive`, the same predicate as `licensePooledBalanceIsLiveSql`); a seat's own
   `status` column is never read. Tests: `subjectRowsSql.test.ts`, `seat-subject-rows.test.ts`.
2. License pools are never re-summed at reset (`fullSubjectToPoolsSummingContributions`); they refill
   to the stored `granted` and their shares still promote. Test: `a due license pool refills…`.
3. `inheritParentCustomerProductLifecycle` in the engine join: a seat takes status, subscription ids and canceled_at
   from its parent in the customer part; no live parent in state means the seat and its grants are
   left out. Tests: `inheritParentCustomerProductLifecycle.test.ts`, `a seat entity tracks from its seat grant…`.
