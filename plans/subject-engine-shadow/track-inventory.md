## (c) Allocated-invoice material excluded, and its hook points

1. **`createAllocatedInvoice`** — `server/src/internal/balances/utils/allocatedInvoice/createAllocatedInvoice.ts:22-80+`. Hook point: `server/src/internal/balances/utils/deductionV2/executeRedisDeductionV2.ts:385-392`, inside the per-cusEnt apply loop, gated on `isUsageBasedAllocatedCustomerEntitlement(customerEntitlement)` and awaited **before** `applyDeductionUpdateToFullSubject`. It runs `setupAllocatedInvoiceContext → computeAllocatedInvoicePlan → evaluateStripeBillingPlan → executeBillingPlan → upsertInvoiceFromBilling`, and a `"declined"` payment error is the special case the surrounding `catch` (`:400-415`) treats as non-error before rolling back.
2. **`paidAllocatedV1` detection** — `server/src/internal/balances/utils/deductionV2/prepareDeductionOptionsV2.ts:33-47` (`fullSubjectHasUsageBasedAllocated`, `shared/utils/fullSubjectUtils/classifyFullSubject.ts:9-28`). Two effects on the ledger's inputs: it **forces `overageBehaviour = "reject"`**, and it makes `executeRedisDeductionV2.ts:89-94` throw `PAID_ALLOCATED`, which routes the whole track to `runPostgresTrackV3`. Net effect on the Redis path: the hook at (1) is unreachable there; the equivalent work lives on the PG path in `server/src/internal/balances/utils/deductionV2/executePostgresDeductionV2.ts`.
3. **Classification helpers not expanded** — `isUsageBasedAllocatedCustomerEntitlement` / `isAllocatedV2CustomerEntitlement`, `shared/utils/cusEntUtils/classifyCusEntUtils.ts:172-196`. Allocated **v2** (arrears-billed continuous features) never invoices mid-track; it only changes reset eligibility (`server/src/internal/customers/actions/resetCustomerEntitlementsV2/getResettableCustomerEntitlements.ts:57-65`, where a price-backed cusEnt is excluded from lazy reset), so that rule is captured in row 23 rather than excluded.
4. **`voidStripeInvoiceIfOpen`, `refreshDeductionUpdate`** (`server/src/internal/balances/utils/allocatedInvoice/refreshDeductionUpdate.ts`) — reachable only from (1).


## Two things the designer should treat as latent bugs, not invariants

- `executeRedisDeductionV2.ts:96-101` is dead: the `paidAllocatedV1 && lock` check sits after an unconditional `paidAllocatedV1` throw at `:89`, so "locks are not supported for paid allocated features" can never be raised.
- Event enqueue differs between lanes: the Redis lane emits an event whenever `!body.skip_event` (`runRedisTrackV3.ts:81`), but the Postgres fallback requires `!body.skip_event && !body.idempotency_key` (`runPostgresTrackV3.ts:62`). Same request, different event-emission semantics depending on which lane served it.
